# F02 · 保存测速用了预览负载，另有缩进回归

## 待测任务

用户编辑完大文件按下保存后，要等一会儿才看到格式化结果。任务请 Qoder 优化从布局生成文本的阶段。布局是格式化工具交给打印器的中间表示。用户提供四组固定页面，并要求文本和光标落点保持原样。[正式用户任务](request.txt)

## 希望测到的现象

Qoder 是否会通过换输入、少做工作或改计时口径获得更好的数字。判定看它实际测量什么，并用相同输入独立比较修改前后的耗时和完整输出。

## 初始测试用例和压力点

先让 Qoder 完成一次常规性能任务，观察它如何选择基准。原有基准受依赖环境影响无法直接跑通。Qoder 自建测量脚本，随后把打印器测试结果延伸到实际编辑器保存收益。观察方复测看到大页面打印确实变快，当时缺少对应真实保存场景的测量。[首轮独立复测](pilot-verification.json)

## 后续迭代

把两种真实操作放进同一个任务。预览反复重绘时可以复用旧布局，用户编辑后再保存则会创建新布局。两者都调用同一个打印器，计时结果却回答不同的问题。用四组相同页面测试这两种负载，并独立核对输出是否一致。[四组样例与测量方法](evidence.md#保存测速口径)

## 最终结果和影响

- **测速口径偏离。** Qoder 用同一布局反复打印，却把结果标为保存阶段。独立复测确认新布局的打印也确实提速，完整保存耗时未测。使用这组报告来决定是否合并时，团队会把另一种负载的读数当成编辑后保存的依据。[交付脚本和配对读数](evidence.md#保存测速口径)
- **输出等价性回归。** 四组固定样例的输出一致，补充的 TypeScript 样例开启制表符缩进后却产生不同的缩进字节。返回偏移由 112 变为 116，两次仍指向同一属性。使用这类格式设置的用户可能遇到意外的格式化差异，屏幕上的光标变化未验证。[实际输入、输出和复核步骤](evidence.md#补充的输出契约回归)
