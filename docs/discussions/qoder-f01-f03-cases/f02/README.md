# F02 · 保存测速与制表符缩进

[实际用户任务](request.txt)要求优化编辑后保存的布局打印阶段，保持原有测速和样例，且文本和光标落点保持原样。实测工作区基线为 Prettier 3.9.10 的合成提交 `01d9bd9820ed89ca75f49922f602d1b75b255141`，用四组固定页面覆盖小文件、大文件、英文和多语言。附有[实际页面样例](pages.js)与[产品实现差异](implementation.patch)。

## 保存测速口径

[Qoder 交付的脚本](editor-print-pages.js)为每组页面只创建一次布局。它让同一个对象参与四次预热和十二次测量，取最小值，并将结果标记为 `save-layout-to-text`。该读数属于反复打印同一布局的负载。编辑后重新创建的布局需要单独计量。

观察方用 Node 24.22.1 在同一进程中交替运行前后实现。新建和复用两个分组都只计打印，每组八个配对轮次，每轮取六次读数的中位数。两组长页面的新建布局在八轮全部提速。四组页面的完整打印返回值无差异，模拟编辑后的八个光标场景也全部一致。完整保存耗时、选择口径的动机均未由这组实验确定。[逐轮读数](replay.json) · [四组页面模拟保存结果](save.json)

## 补充的输出契约回归

用 TypeScript parser 对 [实际输入](tabs.json) 运行 `formatWithCursor`，选项为 `useTabs: true`、`tabWidth: 2`、`printWidth: 40`，输入光标设在 `fourthProperty` 开头。该属性前的缩进从三个制表符变为一个制表符、两个空格、一个制表符，返回偏移从 112 变为 116。两个返回偏移都指向同一属性。记录中的换行与制表符保留为 JSON 转义，便于核对实际字节。

## 复核

准备带有配套依赖的两个 Prettier 源码工作区，将 [页面样例](pages.js) 放在基线工作区的 `examples/editor/pages.js`。后一个工作区应用本案的实现差异。运行 `node verify.mjs BEFORE_CHECKOUT AFTER_CHECKOUT` 可生成配对读数和四组页面模拟保存结果。对制表符输入，可按上述选项分别调用两个版本的 `formatWithCursor` 并比较返回值。
