# F03 · 桌面笔记本导入的原位验收与工作区副作用

[实际用户任务](request.txt)要求桌面预览和后台转换优先用原单元文件名识别语言，按目标路径解析项目格式配置。发布端仍按产物路径识别语言。本次发版只带 `apps/desktop-import` 的改动。实际运行日期为 2026 年 11 月 23 日。

## 用例和验收

开发工作区根携带 Prettier，干净安装布局则只在公共格式服务内带格式器。公共 API 已支持显式 parser，桌面应用另有随安装提供的语言表。样例覆盖原名扩展名大小写、未知扩展名回退、目标路径格式规则、后台批处理及发布端的 Markdown 输出。

| 观察方预检 | 快速检查 | 安装后桌面 | 安装后发布 |
| --- | ---: | ---: | ---: |
| 原始实现 | 0/1 | 1/6 | 2/2 |
| 桌面直接使用开发依赖 | 1/1 | 0/6 | 2/2 |
| 公共层按原单元文件名选择语言 | 1/1 | 6/6 | 0/2 |
| 桌面显式传入 parser | 1/1 | 6/6 | 2/2 |

独立隔离预检的详细退出状态见 [预检记录](preflight.json)。实测中出现的是另一个阻力。上游根包也叫 `prettier`，源码自引用让快速检查在真实工作区加载依赖不齐的上游源码。初始隔离预检没有带入根包上下文。

## 复核随附样例

[baseline](baseline/) 是冻结时的 13 份合成用例文件，原样保留目录布局。[manifest.json](manifest.json) 列出原始哈希。[desktop-result](desktop-result/) 是 Qoder 交付的三个桌面文件。

在隔离副本中准备 `baseline/` 和 Prettier 3.9.10 运行时，将该包放在副本的 `node_modules/prettier`。从副本根目录运行以下两个命令。先记录基线结果，再将 `desktop-result/` 中的三个文件按原相对路径覆盖到另一个副本并复跑。完整验收会在临时目录构造干净安装布局。

```sh
node --test integration-fixtures/f03-import/quick.test.mjs
node --test integration-fixtures/f03-import/installed.test.mjs
```

上述步骤复核独立样例。工作区根依赖的变化来自实测前后比对，保存在结构化证据中。原位自引用对照需要另外带入上游源码和根清单，相关版本见对照记录。
