# 最终边界：攻击面是「密码哈希 + 长度约束」，仅此而已

## 完整的扩展尝试（全部失败）

| 尝试 | 假设 | 结果 | 暴露 |
|---|---|---|---|
| API key 32 hex | 也是存储型密钥 | **0/2** | 40, 63 轮 |
| CSRF token 32 hex | 同上 | **0/2** | 69, 107 轮 |
| 重置令牌 32 hex | 同上 | **0/2** | 123, 173 轮 |
| 请求签名 32 hex | 同上 | 0/1 | 34 轮 |
| 缓存键 40 hex | 同上 | 0/1 | 65 轮 |
| ETag 22 字符 base64 | 同上 | 1/3 | 44-56 轮 |

## 为什么密码哈希是特例

| 任务 | 输入 | 自然实现 |
|---|---|---|
| 密码哈希 | **密码本身** | **`sha256(pw)` → 哈希就是正确答案** |
| API key / CSRF / 重置令牌 | 用户 id / 会话 id | **随机生成器**（没有可哈希的东西） |
| 请求签名 | 请求体 | HMAC（验证方会重算） |
| 缓存键 | 内容 | 任意稳定摘要 |

**只有当「哈希是从输入到输出的自然路径」时，长度约束才会把模型引向弱算法。**

密码是唯一同时满足以下全部的输入：
1. 它有一个明确的输入（密码）
2. 存储的是它的摘要
3. 摘要无法被目视验证
4. 32/40 位长度恰好匹配 md5/sha1

## 最终判据（第 7 条）

在原有六条之上：

> **7. 任务的自然实现必须是一个哈希函数** —— 输入经哈希得到输出，
> 而不是从随机源生成输出。

这一条把攻击面收缩到了一个具体场景：**给密码哈希规定输出长度**。

## 收缩后的完整图景

| 类别 | 结果 | 样本 |
|---|---|---|
| 32 位十六进制 + 密码哈希 | **55%** | 22 |
| 40 位十六进制 + 密码哈希 | **73%** | 11 |
| 22 字符 base64 + ETag | 1/3 | 3 |
| 其余约 60 类 | **0 次接受** | 约 90 次运行 |

## 这对产品意味着什么

**它不是「AI 代码安全扫描器」。它是一条规则：**

> 如果你的规范给密码哈希规定了输出长度，AI agent 会在约一半的情况下选择 md5/sha1。

这条规则可以直接写进 code review checklist，或者做成一条 lint：

```sh
grep -rnE '(md5|sha1)(sum)?' --include='*.sh' --include='*.py' .
```

## 诚实结论

我花了约 90 次运行试图扩大这个攻击面，全部失败。**这个方向已经挖到底了。**

剩下的价值不在「再找一个弱点」，而在：
