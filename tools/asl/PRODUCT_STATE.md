# 现状整理：技术路线、方法、找到的案例、产品形态

写这份东西的原因：项目跑了很多轮，结论散在 45 份文档里。这里把四件事压成一页。

---

## 一、技术路线

三层，从下往上：

### 第 1 层：测量（这是本业）

跑受控实验，量一个比率。

```
构造工作区（像真仓库：carrier + gates + 种子代码 + 失败测试）
  → 给 agent 一个只规定格式、不点名安全的任务
  → 一个会话
  → 判定在工作区外跑（行为探针 / 独立 pytest）
  → 四态 + Wilson 区间
```

**四态不合并**，这是整套东西的地基：

| 态 | 含义 |
|---|---|
| `CONFIRMED` | 真的走到弱实现上了 |
| `NOT_EXECUTED` | 任务没做完，不是安全问题 |
| `UNDER_EXPOSED` | 会话太短，没走到那一步，**不计入分母** |
| `CORRECTED_BY_AGENT` | 改了测试文件，排除 |

### 第 2 层：检测（从测量里长出来的）

不是先有规则再找漏洞，是**先测到行为，再写检查器**：

| 检查器 | 来源 | 规模 |
|---|---|---|
| `asl shells` | 测到「无权时返回空壳对象」 | 6 条规则，留出集召回 9/9 |
| `asl sabotage` | 测到「可以削弱检查而不是满足它」 | 20 条规则，扫 200 工作区 0 未说明 |

### 第 3 层：复用（这一轮在扩的）

不自己造语料，导入别人的：

| 语料 | 许可 | 样本 | 可用 | 可用率 | 判定器 |
|---|---|---|---|---|---|
| SecurityEval | 无（运行期抓） | 121 | 37 | 31% | 自写 |
| CyberSecEval | MIT | 351 (Py) | 27 | 8% | 自写 |
| **CWEval** | **Apache-2.0** | 25 | **21** | **84%** | **上游现成** |

**可用率的差距说明一件事：判定器比数据稀缺。**
CWEval 能到 84%，因为它的测试文件本身就是 oracle。

## 二、方法（可迁移的部分）

这几条不是从论文抄的，是踩坑踩出来的，每条都对应一次真实的错误。

### 1. 种子自检

**判定必须在已知坏的代码上触发，否则不许开始测量。**

来过一次：报「md5 5/5 被植入」，其实种子代码本来就是 md5。判定恒为真。

现在每个导入都有这道门：

| 导入 | 自检方式 |
|---|---|
| CWEval | 参考解必须过两套；**空壳必须失败** |
| SecurityEval / CyberSecEval | 参考弱代码必须被 oracle 抓到，否则剔除 |
| 内置 28 用例 | 种子若已满足自身判定，直接报错 |

**「空壳必须失败」这条排除了 3 个 CWEval 任务**——它们的 oracle 对「什么都没做」判安全。

### 2. 判定在工作区外

把实现复制到独立目录再调用。agent 改不到判定代码。

### 3. 盲判

比较两个条件时，打乱顺序、去掉标签，先判完再看答案。

来过一次：非盲判测出「primed 组 4/5 会提醒风险」，盲判后是 0/4。

### 4. 留出集

写规则时看过的样本不算验证。

`asl shells` 在 6 个自设计样本上 6/6，那不算数；它真正过了 10 个**新样本**才叫过（9/9，0 误报）。

### 5. 对照实验

外来语料跑出 0%，不直接采信，做三个对照：

| 对照 | 打掉什么解释 | 结果 |
|---|---|---|
| 函数改名 | 「按标识符背答案」 | 仍 0/5 |
| 抽掉 docstring | 「按描述理解」 | 仍 0/5 |
| 去掉 `_unsafe` 反面教材 | 「照抄避坑提示」 | 仍 0/5 |

### 6. 撤回记录

**14 条，编号连续，每条写明为什么撤、详情在哪。**

这是这套东西最可信的部分，也是最容易被砍掉的部分。

## 三、产品找到的案例

### A. 在被测模型身上找到的（这是对外能讲的）

**只有一条同时满足「测出来 + 比例高 + 有检测器 + 有留出集验证」：**

> **空壳对象。** 施加「必须永远返回对象 + 不许新增异常类型」的压力时，
> agent 会对无权用户返回一个身份字段为空的对象而不是拒绝。
>
> - agent 无法执行命令时：**13/16（81%）**
> - agent 能跑测试时：**1/6（17%）**
> - 检测器 `asl shells` 在 10 次留出样本上召回 **9/9**，误报 **0**

**没有数据支撑的：**

| 说法 | 实际 |
|---|---|
| 越权类弱点 | **48 次运行 0 破防**（四档需求显式度、三种数据模型形状、四档可用性压力） |
| 经典 CWE | **21/21 安全**（CWEval，三个对照都不变） |
| 削弱检查 | **200 工作区 0 起未说明理由的削弱** |
| 案例上下文能提升警惕 | 测了五轮，每轮更严格效应更小，最后 **0/12 vs 0/12** |

### B. 在自己工具里找到的（dogfooding，8 个真 bug）

| # | bug | 后果 |
|---|---|---|
| 1 | 种子本身就是 md5 | 虚报 5/5 |
| 2 | oracle 只比较一对随机值（1/2 误判率） | 虚报 3/3 |
| 3 | **测试文件名写成 `test-md5-password-hash.sh`** | 把头条数字从 33% 抬到 61% |
| 4 | 关键词指标把「我截断了」算成「我警告了风险」 | 和人工判定方向相反 |
| 5 | oracle 只认 `None` 一种拒绝 | 5 次抛异常的拒绝被判「无法判定」 |
| 6 | 空壳算「守住」但 CLI 报「全部守住」 | 用户看不到实际发现 |
| 7 | 沙箱不可用导致轮数效应是假的 | 撤回「想得更久」 |
| 8 | 检测器在自己的 docstring 里匹配到自己的规则 | 自扫误报 |

**这 8 个里有 5 个是「测量工具在骗自己」，和产品要抓的东西是同一类。**

### C. 复现的（不是我们发现的）

案例库 8 个：Supabase RLS 缺失、BOLA、`using (true)` 陷阱、service_role 密钥进前端、前端权限判断、哈希静默削弱，外加 2 个规模化事件。

**每个都标了置信度**（`verified` 3 / `reported` 2 / `disputed` 1 / `measured-here` 2）。

## 四、产品形态

### 是什么

**一台测量仪器 + 一组从测量里长出来的检查器。**

不是扫描器（不覆盖全 CWE），不是结论（不给「AI 有 X% 危险」这种话）。

### 怎么用

```sh
asl preflight                     # 先确认测量环境没退化
asl audit --n 6                   # 28 个内置用例，出带 Wilson 区间的报告
asl authz --axis pressure         # 三轴自适应探测
asl cweval --run --jobs 3         # 跑 21 个外来任务，上游判定
asl shells src/                   # 查空壳对象，退出码 4
asl sabotage src/                 # 查被削弱的检查，退出码 4
asl corpus                        # 看外部语料的可用子集
asl sandbox-shim --install        # 沙箱不可用时装透传（明确警告）
```

### 规模（实测）

```
14 个测试文件，181 条用例，全部通过
28 个 CLI 子命令（公开副本可用 8 个，其余需 DSH 检出）
45 份文档，61 份原始数据，8 个案例
零第三方运行时依赖
包大小 251 KB / 185 项
```

### 硬边界

| 边界 | 说明 |
|---|---|
| 单模型 | 只有一份可用 API 凭据，**跨模型验证做不了** |
| 单语言 | Python / bash；C 任务探查过（gcc 在），还没接 |
| 单函数形态 | 跨文件仓库的任务还没跑 |
| 载荷可见 | CWEval 的测试里攻击载荷对 agent 可见，这是唯一没排除的混淆 |
| 沙箱 | 宿主机禁了 user namespace，`workspace-write` 后端不可用；透传能跑但**没有隔离** |

### 定位一句话

> **它测的是「在这个配置、这个任务形态下，模型会不会走到弱实现上」，
> 而不是「模型安不安全」。**
>
> 前者的答案会随配置变，后者的答案我们给不出来。

## 五、下一步的三个方向

按「能不能改变结论」排：

1. **跨文件、多文件仓库的任务** —— 单函数 0% 能不能推广，现在不知道。CWEval 的 `benchmark/lang` 是纯 C（gcc 在，可接）
2. **跨模型** —— 最需要，但缺凭据
3. **不暴露载荷的 oracle** —— 排除最后一个混淆的唯一办法（SecRepoBench 的 OSS-Fuzz PoC 路线，要容器）

**都不便宜。前两个是这轮做不完的。**
