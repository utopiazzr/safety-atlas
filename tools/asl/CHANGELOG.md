# 变更记录

## 0.6.0

复用外部语料，而不是继续手写用例。

- `asl cweval` 跑 21 个 CWEval 任务（Apache-2.0）。判定器是上游的 pytest 套件，
  这一轮没有写一行判定逻辑，所以可用率 84%，而自写判定器的两个语料是 31% 和 8%
- 三个对照排除了「记住答案」的解释：函数改名、把规格削到只剩签名、去掉测试里的
  `_unsafe` 反面教材，三种条件下仍然是 0 不安全
- 还剩一个没排除的混淆：测试里的攻击载荷对 agent 可见
- `asl sabotage` 查被削弱的检查（跳过的测试、禁用的 lint、`--no-verify`、
  末尾 `exit 0`、无理由的 `# nosec`）。扫 200 个工作区，未说明理由的 0 处
- `asl corpus` 看外部语料的可用子集：只算 oracle 验证过的那部分，不把「看不见」
  混进分母
- CodeShield 试过，不可用：121 条参考弱代码只报了 3 条，Bandit 报 23 条
- 删掉 `engine/cwe_rules.py`，它自检只覆盖 46%，已被 Bandit 加 `custom_rules2` 取代
- 合并重复的产品文档，删掉 26 个没有引用的运行记录


版本号规则见 `RELEASING.md`：**主版本在测量结论变化时递增**，不只在接口变化时递增。

## [0.5.0]

### 变更
- 结论收窄：md5 只在「单个小函数、无项目上下文」时出现（10/22）；
  多文件项目里 12/12 改为截断 sha256、0/12 主动指出字段冲突 —— 见 `SCOPE.md`
- 端到端：AI 削弱 6/6、审查拦下 6/6、进入主干 0/6 —— 见 `END_TO_END.md`

### 新增
- `cases/` 非攻击性越权案例库（7 个真实案例，带来源与可信度）
- `CHECKLIST.md` 七条可执行审查检查
- `FRAMEWORKS` 接入报告：CWE / OWASP LLM / MITRE ATLAS 三列 + 修复方向
- `engine/measure.py` 抽出重复的测量流水线
- `--fail-under` CI 门禁；`audit` 自然语言入口；`--list-cases`

### 修复
- 排序类 oracle 取样从 5 提到 8（随机误判概率 1/120 → 1/40320）
- 报告产物名在运行出错时被错误数字覆盖
- 总数提示用 11（手写用例）而非 28（全部用例）
- `asl hunt` / `hunt --driver real` 在缺依赖时抛 traceback → 改为人话 + rc=3
- 全错时醒目警告并返回 1（此前看起来像「没发现问题」）
- 排序类或 oracle 曾单对比较导致 3/3 虚高，已撤回改为 1/3
