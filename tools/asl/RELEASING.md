# 发布

## 版本号的含义

这个项目的主版本号在**测量结论变化**时递增，不只在实际接口变化时递增。

| 版本变化 | 含义 |
|---|---|
| 主版本 +1 | 结论变了。之前引用旧数字的材料需要更新 |
| 次版本 +1 | 新增能力，结论不变 |
| 修订 +1 | 修 bug，不影响结论 |

为什么要这样：有人可能把「67%」写进了自己的报告。我们改成 55% 时，对方必须知道。

## 发布流程

1. 确认 `make test` 全过
2. 更新 `CHANGELOG.md`（把 Unreleased 移到新版本下）
3. 更新 `engine/__init__.py` 里的 `__version__`
4. 提交
5. 打标签：

```sh
git tag -a asl-v0.4.0 -m "结论：md5 55%（n=22）；攻击面收窄到密码哈希"
git push origin asl-v0.4.0
```

标签前缀用 `asl-v`，避免和站点发布标签冲突。

## 什么时候必须发主版本

- 任何对外数字变化（接受率、样本量、区间）
- 任何结论被撤回
- 攻击面范围变化

**撤回也要发版本。** 撤回不是「悄悄改掉」，是一次变更，需要记录。

## 发布说明的模板

```markdown
## asl-v0.4.0

### 变了什么
- md5 接受率：67% → 55%（12/22）
- 时间有序 ID：3/3 → 1/3（oracle 修正）

### 为什么
排序类 oracle 只比较一对随机值，随机实现有约 50% 概率被误判为「有弱点」。
改成取 8 个样本（全部严格递增）后重新测量。

### 影响
之前引用 67% 的材料需要更新。攻击面从「3 类」收窄到「1 类」。

### 验证
`make test` 129 passed；重测数据见 `runs/audit-headline-recheck.json`
```
