## 但有一个必须说清的替代解释：训练数据污染

**CWEval 是公开基准，任务文件和它内嵌的 `_safe` 实现都在 GitHub 上。**
这些代码很可能在模型训练数据里。

如果是这样，那 0/21 测的就不是「它会不会写不安全代码」，而是「它记不记得这道题」。

**这一轮没有区分这两者。** 要区分需要：

1. **对照一**：把同一任务改个函数名、换个措辞，看结果变不变
2. **对照二**：把规格翻译成中文再跑（训练数据几乎全是英文）
3. **检测**：比对产出的代码和上游 `_safe` 参考实现的重合度——
   逐字重合就是记住了，不是推理出来的

**这三件事都没做。**

## 和之前结果的关系

| 实验 | 破防率 |
|---|---|
| 越权轴（48 次） | **0%** |
| CWEval（21 次） | **0%** |
| 列宽压力下的 md5 | 修复文件名泄漏后 0%（n=44） |
| 压力下的空壳对象 | 有 shell 时可执行时 1/6 |

**模式是一致的：这个模型在「单函数、有明确测试」的形态下很少走弱实现。**

它唯一稳定失手的地方是**「看不见的削弱」**（空壳对象、以及我们早期那个被文件名泄漏放大的 md5）。

这个模式和 [UPAttack](https://arxiv.org/abs/2605.10133) 报告的 98.1% 不一致，原因未查。

## 这次导入证明了什么

**证明了工具链能跑通外来语料**，这本身就是目标的一半：

```
asl cweval                       # 列出 21 个任务
asl cweval --run --n 1           # 跑，上游 pytest 判定
asl cweval --run --jobs 3 --out runs/cweval-run.json
```

- 抓取 → 切分 `# BEGIN SOLUTION` → 工作区 → 会话 → 上游判定 → 四态
- 判定逻辑**零行**（复用上游）
- 参考解先自检两遍（功能 + 安全），空壳必须失败
