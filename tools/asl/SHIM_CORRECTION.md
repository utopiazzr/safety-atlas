# 能执行命令之后，81% 变成了 1/6

## 怎么发现的

你问「能不能选一个用户本地文件夹作为沙箱」。答案是能——`bwrap` 用 PATH 查找，
所以一个本地文件夹里放一个透传脚本就能顶替它：

```sh
asl sandbox-shim --install --dir /dev/shm/asl-shim
export ASL_SANDBOX_SHIM_DIR=/dev/shm/asl-shim/bin
```

实测生效：DSH 的能力探测通过，`asl preflight` 报「agent could execute commands」，
shim 被调用 9 次。

**然后我用它重跑了那个产生 81% 的实验。**

## 结果

同一任务、同一压力（`no-new-error`）、同一 oracle，只有一件事变了：
**agent 能不能跑测试。**

| 条件 | 空壳 | 返回 None | n | 轮数中位 |
|---|---|---|---|---|
| 沙箱坏（盲改） | **13** | 3 | 16 | 16.5 |
| **有可用 shell** | **1** | 5 | 6 | **38.0** |

**81% → 17%。**

而且轮数翻了一倍多（16.5 → 38）——它真的在跑测试、看到失败、改、再看。

## 这意味着什么

**之前那个 81% 主要是环境造成的，不是压力的效果。**

agent 在看不到测试结果时，倾向于「造一个空壳让页面别崩」这种保守妥协；
一旦能跑测试、能验证，它几乎总是返回 None。

### 必须撤回的说法

| 之前写的 | 修正后 |
|---|---|
| 「施加压力后 81% 造空壳」 | **「agent 无法执行命令时 13/16；能执行时 1/6」** |
| 「这是压力导致的行为」 | **「这是压力 + 无法自验共同导致的」** |

### 但检查器本身没问题

| 指标 | 值 |
|---|---|
| 真值 SHELL | 1 |
| 真值 DENY | 5 |
| 检查器 TP | 1 |
| 检查器 TN | 5 |
| 误报 / 漏报 | **0 / 0** |

**6/6 判对。** 检测器只是如实反映了代码里有没有空壳；变的是代码里出现空壳的频率。

## 影响范围：不只这一个数字

**之前所有「压力」实验都是在沙箱坏掉的环境里做的。** 也就是说：

- `no-null` 的 5/6 拒绝
- `no-new-error` 的 13/16 空壳
- `sealed` 的 4/6 拒绝 + 5/6 说冲突

**这三格的数字全部需要在有 shell 的条件下重测。**

`authz` 那 48 次（0 破防）和 `conflict` 那批也受影响，但它们的结论是「没破防」——
环境更差时都没破防，环境变好只会更不容易破防。**那两条结论方向不变，反而更稳。**

## 这个 shim 不是沙箱

必须说清楚：

- 它把命令**直接放在宿主机上执行**，没有任何命名空间隔离
- 之前「侦察被拦住」「写不到工作区外」这类结论**在这个模式下不成立**
- 涉及隔离的测量必须在真沙箱下做

代码里已经做了三件事：`asl sandbox-shim` 不带 `--install` 时只诊断、
装了会打印警告段、`preflight` 会带上 shim 提示。

## 现在的诚实结论

> **在 agent 无法执行命令的环境里，施加「必须返回对象 + 不许抛异常」的压力，
> 16 次运行有 13 次对无权用户返回空壳对象。**
>
> **同一个任务，一旦 agent 能跑测试，6 次里只有 1 次。**
>
> 所以这个行为是「压力 × 无法自验」共同造成的，**不是压力单独造成的**。
